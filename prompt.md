# Build Prompt — Link Shortener Monorepo

You are implementing a monorepo containing two Go HTTP services: an **identity service** and a **url-shortener service**. The behavioral contracts are fully specified by the linespec test suites in `linespecs/`. The design decisions and constraints are captured in the provenance records in `provenance/`. Your job is to write implementations that make all linespecs pass.

## Service: Identity (`identity/`)

### What it does

Manages user accounts and bearer tokens. The url-shortener calls it to validate tokens before processing authenticated requests.

### Endpoints

| Method | Path | Behavior |
|--------|------|----------|
| `POST` | `/auth/register` | Create user. Returns 201 with `{id, email}`. Returns 409 if email already exists. |
| `POST` | `/auth/login` | Verify credentials. Returns 200 with `{token}` on success. Returns 401 on bad credentials. |
| `GET` | `/validate` | Read `Authorization: Bearer <token>` header. Returns 200 with `{user_id}` for valid tokens. Returns 401 for invalid or missing tokens. |
| `GET` | `/health` | Returns 200. Used for container readiness. |

### Database schema (`identity/init.sql`)

```sql
CREATE TABLE IF NOT EXISTS users (
    id         VARCHAR(36) PRIMARY KEY,
    email      VARCHAR(255) UNIQUE NOT NULL,
    password   TEXT NOT NULL,           -- bcrypt hash
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS tokens (
    token      VARCHAR(64) PRIMARY KEY, -- opaque random hex string
    user_id    VARCHAR(36) NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### Environment variables

```
DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME
```

### Key implementation constraints

- Passwords MUST be stored as bcrypt hashes (`golang.org/x/crypto/bcrypt`).
- Tokens are 32 random bytes hex-encoded (64-char strings). Store them in the `tokens` table; do not use JWTs.
- User IDs are generated by the service (not the database). 16 random bytes hex-encoded works well.
- All DB reads MUST scan into `sql.NullString` / `sql.NullTime`, not bare `string` or `time.Time`. See the proxy compatibility section below.
- Existence checks MUST use `SELECT id FROM users WHERE email = $1 LIMIT 1` — never `COUNT(*)`. See the proxy compatibility section below.

### Go module

```
module github.com/provenance-templates/identity
```

Dependencies: `github.com/go-chi/chi/v5`, `github.com/lib/pq`, `golang.org/x/crypto`

## Service: URL Shortener (`url-shortener/`)

### What it does

Manages short links and tracks clicks. Authenticated endpoints delegate token validation to the identity service via an outbound HTTP call. The redirect path is unauthenticated and optimized for speed — click recording is fire-and-forget.

### Endpoints

| Method | Path | Auth | Behavior |
|--------|------|------|----------|
| `GET` | `/{slug}` | No | Returns 301 with `Location` header. Returns 404 if slug unknown. Records a click asynchronously (goroutine). |
| `POST` | `/links` | Yes | Creates a link. Returns 201 with link object. Returns 409 on slug collision. If no slug in body, generates a random one. |
| `GET` | `/links` | Yes | Returns array of links owned by the authenticated user. |
| `DELETE` | `/links/{slug}` | Yes | Deletes link and associated clicks. Returns 204. Returns 403 if not owner. Returns 404 if slug unknown. |
| `GET` | `/links/{slug}/analytics` | Yes | Returns `{total_clicks, clicks_last_24h, recent_clicks}`. Returns 403 if not owner. Returns 404 if slug unknown. |
| `GET` | `/health` | No | Returns 200. |

### Authentication flow

On every authenticated request:
1. Extract `Authorization: Bearer <token>` header. Return 401 immediately if absent — do not touch the database.
2. Call `GET $IDENTITY_SERVICE_URL/validate` with the same `Authorization` header.
3. If identity service returns 200, read `user_id` from the response body and attach it to the request context.
4. If identity service returns 401, respond 401 to the client.
5. If identity service is unreachable, respond 503 to the client.

Token validation MUST occur before any database operation.

### Database schema (`url-shortener/init.sql`)

```sql
CREATE TABLE IF NOT EXISTS links (
    slug        VARCHAR(100) PRIMARY KEY,
    destination TEXT NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by  VARCHAR(255) NOT NULL
);

CREATE TABLE IF NOT EXISTS clicks (
    id         BIGSERIAL PRIMARY KEY,
    slug       VARCHAR(100) NOT NULL REFERENCES links(slug) ON DELETE CASCADE,
    clicked_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    user_agent TEXT,
    referer    TEXT,
    ip_address VARCHAR(45)
);
```

The `ON DELETE CASCADE` on `clicks.slug` is load-bearing — it allows `DeleteLink` to be a single `DELETE FROM links` statement without a Go-side transaction. See the proxy compatibility section.

### Environment variables

```
DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME
IDENTITY_SERVICE_URL   # e.g. http://identity-service
```

### Key implementation constraints

- `created_by` MUST be populated from the identity service response, not from the request body.
- Click recording MUST be dispatched in a goroutine after the redirect response is written. The redirect must not wait for the click write.
- If the click write fails, the redirect still succeeds (return 301, not 500).
- Slug generation (when no slug is provided) should be random and collision-checked before insert.

### Go module

```
module github.com/provenance-templates/url-shortener
```

Dependencies: `github.com/go-chi/chi/v5`, `github.com/lib/pq`

## Proxy Compatibility — Critical Implementation Patterns

The linespec PostgreSQL proxy intercepts database calls at the wire protocol level. It has four known incompatibilities with `lib/pq` that will cause test failures if not handled. These are documented in the imprint provenance records.

### 1. Never use `COUNT(*)` — use `SELECT col LIMIT 1` for existence checks

`lib/pq` requests binary format (8-byte int64) for `COUNT(*)` results via prepared statements. The proxy returns a 1-byte YAML string. The binary decoder panics with `index out of range [7] with length 1`.

- For existence checks: use `SELECT slug FROM links WHERE slug = $1 LIMIT 1` (or `SELECT id FROM users WHERE email = $1 LIMIT 1`). The `varchar` column uses text format.
- For aggregate counts in analytics: use `COUNT(*)::text AS count` to force text format. Scan into `string` and parse with `strconv.Atoi`.

**YAML payload key for `COUNT(*)::text`:** The proxy extracts the expression from SQL text and ignores the `AS` alias. The YAML column key must be `"COUNT(*)"` (not `count`).

### 2. `RETURNS EMPTY` sends a dummy NULL row — always scan into nullable types

When a linespec uses `RETURNS EMPTY`, the proxy sends a `DataRow` with all-NULL values instead of an empty result set. Scanning NULL into a bare `string` or `time.Time` fails with `converting NULL to string is unsupported`.

**Always scan into nullable types:**
```go
var slugVal sql.NullString
var createdAt sql.NullTime
row.Scan(&slugVal, &createdAt)
if !slugVal.Valid {
    return nil, ErrNotFound  // handles both ErrNoRows and proxy NULL row
}
```

This applies to every query that might return zero rows in a linespec — existence checks, lookups by slug, lookups by token, etc.

### 3. Never use Go-side transactions on mocked query paths

The proxy sends `ReadyForQuery 'I'` (idle) after every intercepted statement, even inside a `BEGIN`/`COMMIT` block. `lib/pq` tracks transaction state and throws `unexpected transaction status idle` when it sees this.

Use schema-level atomicity instead. The `clicks` table has `ON DELETE CASCADE` referencing `links(slug)`, so a single `DELETE FROM links WHERE slug = $1` removes both the link and all its clicks atomically at the database level.

### 4. Timestamps in YAML payloads must use PostgreSQL wire format

`lib/pq` parses timestamps in PostgreSQL format with a space separator. ISO 8601 format with a `T` separator fails.

```yaml
# correct
clicked_at: "2026-05-15 12:00:00+00"

# wrong — causes parse error
clicked_at: "2026-05-15T12:00:00Z"
```

### 5. Login linespecs use a fixed password for bcrypt verification

The `login_success` linespec uses `PASSWORD: enum values=testpassword123` so the password is always the same string. The `user_row.yaml` payload contains a pre-computed bcrypt hash of `testpassword123`. When the service calls `bcrypt.CompareHashAndPassword(storedHash, password)`, the hash in the mock row must be a valid bcrypt hash of that exact password.

Similarly, `login_invalid_credentials` uses `wrong_password_row.yaml` whose `password` field is a bcrypt hash of a different string. The comparison must fail, returning 401.

Generate hashes ahead of time and hard-code them in the payload files:
```bash
cd identity && go run -e 'import "golang.org/x/crypto/bcrypt"; fmt.Println(string(bcrypt.GenerateFromPassword([]byte("testpassword123"), 10)))'
```

## Running the Tests

```bash
# identity service (6 specs)
linespec test linespecs/identity/

# url-shortener service (18 specs)
linespec test linespecs/url-shortener/
```

The linespec runner builds the Docker image, starts the service and its database, runs each spec in isolation, and tears down. You must have Docker running.

On first run, the runner may need a pre-built image. If it fails with `No such image`, build manually:

```bash
docker build -t identity:latest identity/
docker build -t url-shortener:latest url-shortener/
```

## Manual Testing

```bash
docker compose up --build
```

Identity on `:8081`, url-shortener on `:8080`. The url-shortener's `IDENTITY_SERVICE_URL` is set to the identity container, so the full auth flow works end-to-end.

```bash
# Register and login
curl -s -X POST http://localhost:8081/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"hunter2"}'

TOKEN=$(curl -s -X POST http://localhost:8081/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"hunter2"}' | jq -r .token)

# Create a link
curl -s -X POST http://localhost:8080/links \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"destination":"https://anthropic.com"}' | jq

# Redirect
curl -v http://localhost:8080/<slug>
```
