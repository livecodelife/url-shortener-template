Build a monorepo containing two Go services — `identity/` and `url-shortener/` — each with its own Go module, Dockerfile, and PostgreSQL schema. Use a `go.work` at the root to tie the modules together. Run tests with `linespec test linespecs/identity/` and `linespec test linespecs/url-shortener/`. Add a `docker-compose.yml` at the root for manual end-to-end testing.

The linespec PostgreSQL proxy has four quirks that will cause silent failures if not handled. First, `lib/pq` requests binary int8 encoding for `COUNT(*)` but the proxy returns text — use `SELECT col LIMIT 1` for existence checks and `COUNT(*)::text` for aggregates (scanned into `string`, parsed with `strconv.Atoi`). Second, `RETURNS EMPTY` sends a dummy all-NULL row instead of no rows — scan every nullable query result into `sql.NullString`/`sql.NullTime` and treat `.Valid == false` as not-found. Third, Go-side transactions (`BEGIN`/`COMMIT`) break because the proxy sends `ReadyForQuery 'I'` after each intercepted statement — use schema-level `ON DELETE CASCADE` instead. Fourth, timestamps in YAML payloads must use PostgreSQL wire format (`"2026-01-01 00:00:00+00"`), not ISO 8601 (`"2026-01-01T00:00:00Z"`).
